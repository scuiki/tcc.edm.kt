GUIA DE EXECUÇÃO — MIGRAÇÃO SPRING 2019
=======================================

Referência: docs/plano_migracao_spring2019.md


VISÃO GERAL
-----------

O processo tem duas etapas distintas:

  ETAPA A — Agente Claude Code (1 agente, ~10–20 min)
    Faz todas as mudanças de código e organização de arquivos:
    verificações, movimentação de dados, edição de .py e notebooks,
    atualização de harness e documentação.
    NÃO re-executa notebooks.

  ETAPA B — Harness (você roda manualmente, ~1–2h por plan)
    Re-executa cada notebook na ordem correta, regenerando
    resultados e textos analíticos com os novos dados.


1 AGENTE É O SUFICIENTE?
------------------------

Sim. Todas as mudanças do plano são edições de arquivo — Python,
JSON de notebooks, Markdown e operações de filesystem. Um único
agente consegue fazer tudo na sequência correta.

A única exceção são as re-execuções de notebook (via harness), que
precisam rodar fora do agente porque o harness chama o Claude Code
internamente como subprocesso.

RESET DE STATUS DO HARNESS (parte do Passo A)
----------------------------------------------

Após editar os notebooks, o agente deve também resetar as tasks
do harness que precisam ser re-executadas com os novos dados.
Diga ao agente para fazer isso, ou faça manualmente:

  preprocessing.json  → tasks 1, 2, 3, 4, 5  → status: "pending"
  kc_generation.json  → tasks 1, 2, 3, 4, 5, 7 → status: "pending"
                        (task 6 = label_kc_correctness, manter "pending" — não rodar)
  bkt.json            → tasks 1, 2, 3, 4, 5 já estão "pending" — nada a fazer
  eda.json            → tasks 1, 2, 3, 4, 5, 6, 7, 8 → status: "pending"

Os arquivos ficam em .harness/plans/


ETAPA B — HARNESS (após o agente terminar)
------------------------------------------

Execute cada plan na ordem abaixo, a partir da raiz do repositório.
O flag --loop faz o harness continuar até todas as tasks estarem
completas ou até falhar.

  1. Preprocessing (necessário primeiro — gera os pkl):

       python .harness/runner.py --plan .harness/plans/preprocessing.json --loop

  2. KC Generation (depende do pkl gerado acima):

       python .harness/runner.py --plan .harness/plans/kc_generation.json --loop

     Atenção: a task 6 (label_kc_correctness) está como "pending" por design
     — ela custa ~$2-3 e só é necessária para o Code-DKT (notebook 06).
     O harness vai parar nela se todas as dependências estiverem ok.
     Se quiser rodar só a task 7 (validação srcML), use:

       python .harness/runner.py --plan .harness/plans/kc_generation.json --task 7

  3. BKT (depende do pkl gerado no step 1):

       python .harness/runner.py --plan .harness/plans/bkt.json --loop

  4. EDA (independente do pkl — pode rodar em qualquer ordem):

       python .harness/runner.py --plan .harness/plans/eda.json --loop

     O EDA demora ~30 min (análise completa do dataset).
